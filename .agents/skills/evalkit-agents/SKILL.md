# Add an Evalkit agent

Read `../evalkit/SKILL.md` for shared constraints and `../../../sites/evalkit.leostera.dev/src/content/docs/manual/agents.md`. Inspect `../../../packages/core/src/index.ts` (`AutAdapter`, `AutContext`, `AutEvent`), `../../../examples/starter/agents/greeting-agent.ts`, and `../../../packages/agents/src/index.ts` before editing.

1. Identify the **Agent Under Test (AUT)**: the assistant, process, or service whose behavior the eval measures, not the scorer that grades it. Its adapter starts a fresh session per run, receives user messages, and emits the evidence scorers inspect. Decide whether to reuse `piAgent()` for the local Pi CLI or implement `defineAgent({ identity, start })` for a different agent (`runtimes` defaults to in-process local). Do not add new agent kinds; adapt the agent with `defineAgent`. `agentsSdk()` currently throws; do not claim it is a usable remote adapter.
2. Give the new agent a stable, unique lowercase kebab-case `identity.id`, meaningful `name`/`kind` and optional version. A declared runtime has `kind` and optional serializable `configuration`; the local CLI selects the first declared runtime among local/remote/sandbox, or lets an adapter without runtimes use its default. Only declare a runtime your adapter really supports.
3. In `start({ context, runtime, transcript, attach })`, initialize a **new run session**. Use `context.workspace.root` for candidate-visible data. Treat `context.evaluatorWorkspace.root` as trusted-only: never expose its path or all its contents to the AUT. `context.data[id]` holds candidate dataset values. A controlled experiment may deliberately read a specific evaluator dataset and pass only that treatment input to the model (for example, a `memory=on` arm); document that this tests injected context, not retrieval. Read and validate `context.parameters` if flags or matrix axes should affect agent behavior. Run tools and agent CLIs through `context.shell` (`exec`, `spawn`, `readFile`/`writeFile`/`list`), so they run where the project's `isolation` puts them (`none()` host default, `container({ image, network })`, `sandboxExec({ allow, read, deny, env })`); services from config `fixtures` are at `context.fixtures[name].url`. Pass `context.signal` to model calls and tool processes: it aborts when the run reaches a limit (`context.limits`: steps, tokens, time) or is cancelled.
4. Return a session whose `send(message)` resolves after the turn finishes and **returns the turn's result**: a reply string, or `{ reply, toolCalls: [{ name, arguments, result?, id? }], usage, model }`. EvalKit records it in the run's ATXF transcript. `close()` is optional. To record each model call as it happens, write to `transcript` instead: `transcript.assistant({ content, model, usage })` (content is text or ATXF blocks such as `tool_call`), `transcript.toolResult(callId, result, { name, isError })`, optional `transcript.turn('start' | 'end')`, `transcript.subagent(childTranscript)` for sub-agents. For agents ATXF converts (Pi, Claude Code, Codex, Gemini CLI, OpenCode), import the session after each turn: `transcript.import(pi.toAtxf(text))` from `@leostera/atxf/pi`. Usage is ATXF buckets: `{ input, output, cacheRead?, cacheWrite?, reasoning? }`, with cached tokens kept **out** of `input`. Plain values are converted to JSON once; no `JSON.parse(JSON.stringify(...))` casts. Propagate failures so the runner can record them.
5. Import the adapter from an eval; importing an agent alone does not make a run available to the CLI. Add or adapt a predicate; `output` holds the final reply. Test a single eval before a costly suite.

For a coding agent, use a built-in harness: `piAgent()`, `codexAgent()`, `opencodeAgent()` or `claudeCodeAgent()` run the CLI with its own tools, one session per run, through `context.shell` with the message on stdin, and import its native session through ATXF (tool calls, usage and steps included). They default to `config: 'private'`, an empty config directory in `context.shell.home`: supply provider settings with `configFiles` and keys with `env`, or `config: 'user'` for the person's own setup. `model` may be `({ model }) => String(model)` for a matrix axis. For another CLI use `harnessAgent(spec, options)`. For a custom agent, explicitly control its MCP/tool configuration and record real observed tool calls and results. Read and validate `context.parameters` when the model or treatment varies by matrix cell. Do not claim a memory snapshot ablation measures live memory retrieval.

To keep the agent's raw log (or any file) when a passing run's sandbox is removed, call `attach(name, content)` from `start()`'s options, usually in `close()`: `await attach('logs/agent.log', log)`. Names are relative paths of `[A-Za-z0-9._-]` segments; files over 5 MB keep their end; a run's attachments are capped at 20 MB (`artifacts.attachments` in the config). Scorers have the same `attach` on their context.
